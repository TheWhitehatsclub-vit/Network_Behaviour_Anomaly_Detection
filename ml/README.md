# ML Module — Network Behaviour Anomaly Detection

This folder contains the machine learning component of the NBAD project. It uses an **Isolation Forest** model to detect anomalous network traffic.

## What this does

The model learns what "normal" network traffic looks like from real captured traffic data, then flags incoming traffic that deviates from that pattern as a potential anomaly (e.g. a port scan, DoS-style burst, etc.).

## Status

Trained and tested on real captured traffic data. Contamination parameter tuned across two rounds of testing; final value locked in at 0.17, chosen for its stronger detection rate given the project's feedback-loop design (see Person 5's false-alarm button, which absorbs the trade-off in false positives). Full pipeline (train → predict) is working end-to-end.

## Files

| File | Purpose |
|------|---------|
| `train.py` | Trains the Isolation Forest model on real normal traffic, evaluates against real attack datasets, saves `model.pkl` and `feature_means.pkl` |
| `predict.py` | Loads `model.pkl` and `feature_means.pkl`, exposes a `predict()` function for the backend to call |
| `tune.py` | Used to sweep contamination values and compare detection rate vs false-positive rate. Already served its purpose; kept for reference |
| `model.pkl` | The saved, trained model (generated by `train.py`, not hand-written) |
| `feature_means.pkl` | Average value of each feature across normal traffic, used by `predict.py` to explain which feature triggered a flag |

## Usage

**Train the model:**
```bash
python train.py
```
This loads real normal traffic, trains the model, evaluates it against four real attack datasets, prints results, and saves `model.pkl` and `feature_means.pkl`.

**Run a prediction:**
Import `predict()` from this file into your own script — see below.

## The `predict()` function

```python
predict(traffic_row: dict)
```

**Input:** a dictionary with these 8 exact keys (case-sensitive), values already standardised the same way as the training data:
- `Inter_Arrival_Time`
- `Src_Port`
- `Dst_Port`
- `Seq`
- `Ack`
- `Win`
- `Payload_Len`
- `Packet_Length`

**Returns:** a dictionary —
```python
{
    "status": "anomaly" or "normal",
    "anomaly_score": float,       # more negative = more anomalous
    "severity": "low" / "medium" / "high",
    "triggered_by": str           # which feature deviated most from normal
}
```

This is the function the backend (FastAPI) should import and call for each new traffic sample.

## Important: feature order

`sklearn`'s `IsolationForest` does not check column names when predicting — it only looks at column position. `train.py` and `predict.py` both use this exact order, and it must stay consistent everywhere the model is loaded, including in `retrain.py`:

```python
FEATURES = ["Inter_Arrival_Time", "Src_Port", "Dst_Port", "Seq", "Ack", "Win", "Payload_Len", "Packet_Length"]
```

If this order ever differs between files, the model will silently produce wrong predictions with no error message.

## Required input data

Live traffic sent to `/predict` must be standardised the same way as the training data before being passed to `predict()`, or predictions will be meaningless.
