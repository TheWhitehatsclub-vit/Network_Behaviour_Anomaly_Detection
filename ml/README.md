# ML Module — Network Behaviour Anomaly Detection

This folder contains the machine learning component of the NBAD project. It uses an **Isolation Forest** model, trained on real standardised network traffic, to detect anomalous behaviour.

## Status

Trained on real data (not fake/sample data). Train/test split used for honest accuracy measurement. Overall accuracy ~85% (see `metrics.py` output). Includes safety checks for feature-order mismatches and missing/NaN input values — both fail loudly with a clear error instead of silently returning wrong predictions.

## Files

- `train.py` — Trains the Isolation Forest model on real normal traffic (80/20 train/holdout split), saves `model.pkl` and `feature_means.pkl`
- `predict.py` — Exposes `predict()` for the backend to call on new traffic
- `retrain.py` — Exposes `retrain()` for the feedback loop — retrains on accumulated false positives
- `metrics.py` — Calculates Precision, Recall, F1, and confusion matrix on the held-out test set
- `visualize.py` — Generates `score_distribution.png` (normal vs attack score histogram) and `confusion_matrix.png`
- `check_scores.py` — Prints min/max/mean anomaly score per traffic type, useful for sanity-checking severity thresholds
- `tune.py` — Sweeps contamination values to compare false-positive rate vs detection rate; results saved in `results.txt`. Already served its purpose (contamination=0.17 chosen); kept for reference
- `test_predict.py` — Quick manual sanity check: runs `predict()` on one real normal row and one real attack row
- `model.pkl` — Saved, trained model (generated by `train.py`)
- `feature_means.pkl` — Per-feature mean values, used by `predict()` to determine `triggered_by`
- `normal_holdout.csv` — The 20% of normal traffic held out from training, used by `metrics.py` and `visualize.py`
- `results.txt` — Output of `tune.py`'s contamination sweep

## Usage — run in this order

```bash
python train.py
python metrics.py
python visualize.py
```
`train.py` must run first — it creates `model.pkl`, `feature_means.pkl`, and `normal_holdout.csv`, which `metrics.py` and `visualize.py` both depend on. Only re-run `train.py` if you want to rebuild the model from scratch (this resets any accumulated retrain feedback).

`retrain.py` is not run directly — it's called by the backend's `/feedback` endpoint with real false-positive data. Don't run its test block after initial verification, since it adds a row to the training data each time.

## The `predict()` function

```python
from ml.predict import predict

predict(traffic_row: dict)
```

**Input:** a dict with these 8 keys (values must be standardised, same scaling as training data):
- `Inter_Arrival_Time`, `Src_Port`, `Dst_Port`, `Seq`, `Ack`, `Win`, `Payload_Len`, `Packet_Length`

**Important — missing fields:** real captured traffic is not always fully populated. Non-TCP traffic (e.g. QUIC/UDP) often lacks `Src_Port`, `Dst_Port`, `Seq`, `Ack`, `Win`, or `Payload_Len`. `predict()` will raise a `ValueError` if any of the 8 required fields are missing or NaN, rather than guessing. The caller (backend) needs to filter or route non-TCP traffic separately, since this model currently only evaluates traffic with all 8 fields present.

**Returns:**
```python
{
    "status": "anomaly" or "normal",
    "anomaly_score": float,
    "severity": "low" / "medium" / "high",
    "triggered_by": str  # feature that deviated most from normal
}
```

## The `retrain()` function

```python
from ml.retrain import retrain

retrain(false_positive_rows: list)
```

**Input:** a list of dicts, each with the same 8 keys as above.

**Returns:**
```python
{
    "status": "success",
    "rows_added": int,
    "total_training_rows": int
}
```

## Safety checks

`sklearn`'s `IsolationForest` matches columns by position, not name. `predict.py` and `retrain.py` both check the loaded model's actual trained feature order (`model.feature_names_in_`) against their own `FEATURES` list, and raise a clear error immediately if they ever mismatch.

`predict.py` also checks for missing/NaN values in the input row before predicting, and raises a clear error listing which fields were missing, instead of silently returning a meaningless prediction.

## Required input columns

Incoming traffic must be standardised the same way training data was, and contain (fully populated, no missing values):
`Inter_Arrival_Time`, `Src_Port`, `Dst_Port`, `Seq`, `Ack`, `Win`, `Payload_Len`, `Packet_Length`
